# composites

> **What this covers:** Mid-level reusable building blocks (cards, rows, the newsletter form) and the persistent page chrome (header nav + footer).

## What
- **Composites** are mid-level components that sit between primitives and sections. They compose one or more primitives (`GoldRule`, `MicroSigil`, `MottoLine`, `Sigil`) plus their own markup into a labelled, reusable unit (a credential row, a pricing card, the newsletter form). They are content-agnostic: every composite takes its copy/data through props and renders no data of its own.
- **Chrome** is the persistent shell rendered on every page — the sticky `HeaderNav` and the page `Footer`. Chrome is mounted once by the app shell (see `spec/app-shell.md`), not per-section.
- Composites are consumed by **sections** (the per-page content blocks); sections pass data down into composites. Composites in turn consume **primitives** (`showcase/components/primitives/*`). This domain owns nothing about page layout or routing.
- Styling is **inline-style based** (the `style={{...}}` object pattern) using CSS custom properties for the brand palette: `--ink-green`, `--parchment`, `--gold`, `--gold-warm`, and the font vars `--font-cormorant`, `--font-eb-garamond`. A few Tailwind utility classes appear only in `HeaderNav` for responsive show/hide (`hidden sm:flex`, `flex sm:hidden`).

## Where
- `showcase/components/composites/CredentialRow.tsx` — a single `<li>` credential entry in a two-column grid (numeral + details). Props: `numeral`, `title`, `year`, `institution`, `specialization?`, `className?`. Pure server component (no `"use client"`, no primitives). Caller is responsible for wrapping these in a `<ul>`/`<ol>`.
- `showcase/components/composites/NewsletterForm.tsx` — email capture form with client-side validation, a **pending** state, a thank-you state, and a network-failure state. Props: `buttonLabel?` (default `"Join the Vespers"`), `compact?` (row layout + tighter sizing when true), `className?`, `source?` (provenance tag passed to the backend; default `"unknown"`). **Client component** (`"use client"`). Uses primitive `GoldRule` (in the success state) and calls `useMutation(api.subscribers.subscribe)` to persist via Convex — see How and `spec/convex.md`. Carries a silent anti-spam stack — a hidden honeypot field plus render-timing — whose signals (`hp`, `elapsedMs`) are sent to the mutation but never branched on in the UI (see How).
- `showcase/components/composites/ContactForm.tsx` — full contact form (name + email + message) with the same client-side validation/`pending`/thank-you/failure lifecycle and the same anti-spam stack as `NewsletterForm`. Fields: `email` (required, `EMAIL_RE` client guard), `message` (required, non-empty `<textarea rows={5}>`), and an optional `name`. Props: `source?` (provenance tag; default `"unknown"`), `className?`. **Client component** (`"use client"`). Uses primitive `GoldRule` (in the success state) and calls `useMutation(api.messages.submitContact)` to persist via Convex — see How and `spec/convex.md`. Reuses the gold/parchment inline styling (a shared `fieldStyle` helper for the three inputs) and the same a11y pattern (`useId`/`aria-*`/`role="alert"`/`noValidate`).
- `showcase/components/composites/NewsletterForm.test.tsx` — Vitest + Testing Library suite for `NewsletterForm`. **Mocks `convex/react` (`useMutation`) and `@/convex/_generated/api`** so it runs with no real deployment. Covers: renders email field + button; invalid-email shows a `role="alert"` error **and makes no mutation call**; valid submit calls `subscribe` once with the trimmed email + `source` (plus the `hp`/`elapsedMs` anti-spam fields) and swaps the form for the "Inscribed" confirmation (input disappears); a custom `source` is forwarded; a **rejected** mutation shows the "the ink did not take — try again" error (not the confirmation); the input + button disable while the call is **pending**; and custom `buttonLabel` is respected.
- `showcase/components/composites/ContactForm.test.tsx` — Vitest + Testing Library suite for `ContactForm`. **Mocks `convex/react` (`useMutation`) and `@/convex/_generated/api`** so it runs with no real deployment. Covers: renders name/email/message fields + Send button; invalid-email shows a `role="alert"` error **and makes no call**; empty-message shows the "a few words, please" error **and makes no call**; valid submit calls `submitContact` once with trimmed `email`/`message`, default `source`, and the anti-spam fields (`hp` a string, `elapsedMs` a number) then swaps in the "Inscribed" confirmation (inputs disappear); a custom `source` is forwarded; `name` is omitted when blank and trimmed-then-included when provided; a **rejected** mutation shows the "the ink did not take — try again" error (not the confirmation); the email/message/Send disable while **pending**; and the hidden honeypot (`input[name="company"]`, `tabIndex=-1`, `aria-hidden`) is present but not a reachable labeled input.
- `showcase/components/composites/PillarCard.tsx` — compact centered "pillar" card: icon, uppercase name, rule, short distillation. Props: `motif` (`MicroSigilMotif`), `name`, `distillation`, `className?`. **Client component**. Uses primitives `MicroSigil` (size 36) and `GoldRule`.
- `showcase/components/composites/PillarPanel.tsx` — larger sibling of `PillarCard` (bigger sigil/heading, left-aligned long-form `body`). Props: `motif` (`MicroSigilMotif`), `name`, `body`, `className?`. **Client component**. Uses primitives `MicroSigil` (size 64) and `GoldRule`.
- `showcase/components/composites/PriceCard.tsx` — bordered pricing card: name, rule, optional duration, price (with optional parenthetical `priceNote`), description. Props: `name`, `duration?`, `price`, `priceNote?`, `description`, `className?`. **Client component**. Uses primitive `GoldRule`.
- `showcase/components/composites/PriceNote.tsx` — small centered addendum block under pricing (a `+` glyph, uppercase title, body). Props: `title`, `body`, `className?`. Pure server component (no `"use client"`, no primitives).
- `showcase/components/chrome/Footer.tsx` — page footer: `GoldRule`, `MottoLine`, a `compact` `NewsletterForm`, a "write directly" cross-route link to the contact form (`<Link href="/#contact">`, resolving to the `ContactForm` in H8), and the "Ora et labora" / © credit lines. **Client component** (transitively, because it embeds `NewsletterForm` and `MottoLine`). Uses primitives `GoldRule`, `MottoLine`, plus composite `NewsletterForm`. No props.
- `showcase/components/chrome/HeaderNav.tsx` — sticky top nav: brand `Sigil` + wordmark, desktop link cluster (Home · About · Newsletter brass-plaque), mobile hamburger, and a full-screen mobile menu overlay portaled to `document.body`. **Client component**. Uses primitive `Sigil` and hook `useScrolled(80)`; Next `Link`, `usePathname`, `createPortal`. No props.

## How
- **`NewsletterForm` persists to Convex (email is NOT sent yet).** `onSubmit` calls `e.preventDefault()` and tests the trimmed email against a local regex (`EMAIL_RE = /^[^@\s]+@[^@\s]+\.[^@\s]+$/`); on failure it sets the inline "a valid email, please" error and **returns without any network call**. On a valid email it sets `pending` (disabling input + button), `await`s `subscribe({ email: email.trim(), source, hp, elapsedMs })` — the `useMutation(api.subscribers.subscribe)` handle — then on resolve flips `submitted` to `true` (swapping in the static "Inscribed. A response will arrive in due time." message), or on reject shows the inline "the ink did not take — try again" error and keeps the entered email for retry; `pending` clears either way (`finally`). The mutation **stores** the address (server-side validates + dedups + inserts) but **sends no email** — that is the Resend phase (a documented seam only). See `spec/convex.md` for the full backend contract. The local regex remains as instant offline UX; the server regex is authoritative.
- **`ContactForm` persists to Convex via `submitContact`.** `onSubmit` calls `e.preventDefault()`, then runs two client guards in order: the trimmed email against the same `EMAIL_RE` (failure → inline "a valid email, please", no network call), then a non-empty trimmed `message` (failure → inline "a few words, please", no network call). On passing both it sets `pending` (disabling email/message/Send), `await`s `submitContact({ email: email.trim(), message: message.trim(), name: name.trim() || undefined, source, hp, elapsedMs })` — the `useMutation(api.messages.submitContact)` handle — then on resolve flips `submitted` to `true` (same "Inscribed. A response will arrive in due time." message), or on reject shows the same "the ink did not take — try again" error and keeps the entered values for retry; `pending` clears either way (`finally`). Optional `name` is trimmed and **omitted** (sent as `undefined`) when blank. See `spec/convex.md` for the backend contract.
- **Silent anti-spam stack (both forms — no UI tell).** Each form renders a hidden honeypot text input `name="company"` wrapped in an `aria-hidden="true"` off-screen container (`visuallyHidden` style), with `tabIndex={-1}` and `autoComplete="off"` on the field itself, bound to an `hp` state string. Each form also captures **render-timing**: a `renderedAt` ref is set in a mount `useEffect` (`renderedAt.current = Date.now()`) — deliberately **not** during render, to satisfy the `react-hooks/purity` lint rule — and on submit `elapsedMs` is computed as `Date.now() - renderedAt.current`, or **`undefined`** when `renderedAt.current` is still `null` (so a pre-mount submit never carries a misleading timing the server could false-drop on). Both `hp` and `elapsedMs` are passed to the mutation, but **the client never branches on them** (no error, no UI difference): the server alone decides and returns an opaque success. See `spec/convex.md` for how the backend weighs these signals.
- `NewsletterForm` / `ContactForm` accessibility: both use `useId()` for field/error ids (`ContactForm` mints `nameId`/`emailId`/`messageId`/`errorId`); every `<label>` is visually hidden (`visuallyHidden` style object); errors are wired via `aria-invalid` + `aria-describedby` and surfaced through `role="alert"`. Both set `noValidate` so the JS guards are the sole validation path (native browser validation is disabled despite `type="email" required` / `required` on the textarea). Hover styling on the submit button is done imperatively via `onMouseEnter`/`onMouseLeave` mutating `e.currentTarget.style`. The honeypot input is intentionally **not** a reachable labeled control.
- **`HeaderNav` hydration + portal pattern (caveat):**
  - It keeps a `mounted` flag: `const [mounted, setMounted] = useState(false)` plus `useEffect(() => setMounted(true), [])`. This is an **SSR hydration guard** — `document.body` does not exist during server render, so the portal must only run on the client. The render line is `{mounted && overlay ? createPortal(overlay, document.body) : null}`; without the guard, hydration would mismatch / `document` would be undefined on the server.
  - The mobile menu overlay is **portaled to `document.body`** via `createPortal`, escaping the sticky `<header>` stacking/overflow context so the fixed full-screen overlay (`position: fixed; inset: 0; zIndex: 100`) covers the viewport reliably.
  - The **hamburger is hidden on desktop** and desktop links hidden on mobile purely via Tailwind responsive classes: the link cluster uses `className="hidden sm:flex"` and the hamburger button uses `className="flex sm:hidden …"`. (This is the only place Tailwind classes drive layout; everything else is inline styles.)
  - When the menu is open, a second effect locks body scroll (`document.body.style.overflow = "hidden"`) and restores the previous value on cleanup.
  - Active-link highlighting derives from `usePathname()`: `isHome = pathname === "/"`, `isAbout = pathname === "/about" || pathname.startsWith("/about/")`. The sticky header changes background/blur/border once scrolled past 80px via `useScrolled(80)`.
- **Client vs server split:** `CredentialRow` and `PriceNote` are plain server components (no hooks, no `"use client"`). Everything that imports a `"use client"` primitive (`GoldRule`, `MicroSigil`, `MottoLine`, `Sigil`) or uses state/effects is a client component: `NewsletterForm`, `ContactForm`, `PillarCard`, `PillarPanel`, `PriceCard`, `Footer`, `HeaderNav`. If you add a server-only consumer, prefer the two pure composites or wrap client ones accordingly.
- **Primitive dependencies (other domain — see `spec` for primitives):** `GoldRule` → NewsletterForm, ContactForm, PillarCard, PillarPanel, PriceCard, Footer. `MicroSigil` (+ `MicroSigilMotif` type) → PillarCard, PillarPanel. `MottoLine` → Footer. `Sigil` → HeaderNav. Changing those primitives' APIs ripples into this domain.
- **Gotchas / placeholders:**
  - No `mailto:[email]` placeholders remain in chrome. The Footer "write directly" affordance is a real cross-route `<Link href="/#contact">` to the H8 `ContactForm`; the H8 contact affordance is a wired `ContactForm` (not a mailto). No section or chrome surface silently discards input.
  - All composites accept an optional `className` and merge it onto the root element, but visual styling is inline — a passed class can only add to (not easily override) the inline styles.
  - `NewsletterForm` and `ContactForm` both default their props object (`NewsletterForm({...}: NewsletterFormProps = {})` / `ContactForm({...}: ContactFormProps = {})`), so each is safe to render with no props (`<NewsletterForm />` / `<ContactForm />`), as the Footer and tests do.
  - `ContactForm` and `NewsletterForm` are deliberately silent about spam: a dropped submission still resolves and shows the "Inscribed" confirmation, so do **not** add client-side honeypot/timing error branches — the opacity is the design (see the anti-spam note in How).
  - `PriceCard.priceNote` renders inside parentheses appended to the price; `duration` is uppercased small-caps styling. Both are optional and omitted cleanly when absent.
