## Conventions block (read once; reference from every step)

- All app + backend code lives under `showcase/`. Run every `npm`/`npx` command from `showcase/`.
- Path alias `@/*` → `./` (relative to `showcase/`). So `@/convex/_generated/api` resolves to `showcase/convex/_generated/api`.
- **Convex backend:** `showcase/convex/*.ts` (functions) + `showcase/convex/_generated/*` (codegen — do not hand-edit).

- **Form:** `showcase/components/composites/NewsletterForm.tsx`.
- **Form callers:** `showcase/components/sections/H8.tsx`, `showcase/components/chrome/Footer.tsx`.

### Env vars
- `NEXT_PUBLIC_CONVEX_URL` — public deployment URL, read by the browser client. Written into `showcase/.env.local` by `npx convex dev`. Must also be set in Vercel (preview + production).
- `CONVEX_DEPLOYMENT` — written by the Convex CLI; used by the CLI only. Not read by the browser.
- `.env.local` is git-ignored (root + `showcase/.gitignore`). Never commit secrets.

### `source` values
- `"h8"` (the H8 primary CTA), `"footer"` (compact footer form), `"unknown"` (default). No other placements exist in code today.

### Voice / copy (locked)
- Success (unchanged): *"Inscribed. A response will arrive in due time."*
- Invalid email (unchanged): *"a valid email, please"*
- Network/server failure (new): *"the ink did not take — try again"*

### Validation regex (shared by client + server)
- `EMAIL_RE = /^[^@\s]+@[^@\s]+\.[^@\s]+$/`

### Resend seam (DO NOT BUILD THIS ITERATION)
- The `subscribe` mutation's insert branch is where a future `await ctx.scheduler.runAfter(0, internal.emails.sendWelcome, { email })` will go. Leave a one-line comment marking it; write no email code.

## Build orchestration (subagents)

This plan is executed by **orchestrated subagents**, not a single linear pass. The main agent acts as orchestrator; it does not hand-write step output itself except for trivial one-line edits.

**Per-step pattern (implementer → adversarial verifier):**
1. **Implementer subagent** — given one step's full block (Inputs/Outputs/Implementation) plus the Conventions block, it makes exactly that step's changes and returns a structured summary (files touched, decisions, anything deviating from the step).
2. **Verifier subagent** — given the same step's **Acceptance criteria** and the implementer's diff, it independently checks each criterion and returns pass/fail per criterion with evidence. It is prompted to *try to fail* the step (did the form still make a network call on invalid email? is the dedup actually case-insensitive? did `layout.tsx` accidentally gain `"use client"`?). A step is DONE only when every criterion passes; on any fail, the orchestrator re-dispatches the implementer with the verifier's findings.

**Parallelism (from the dependency graph):**
- Sequential spine: `0.1 → 0.2 → 1.1 → 1.2 → 3.1 → 3.2 → 4.1 → 5.1`.
- **Parallel fan-out after 0.2:** Step **1.1** (schema) and Step **2.1** (`ConvexClientProvider`) have no interdependency — run their implementer subagents concurrently. **2.2** depends on 2.1; **1.2** depends on 1.1. **3.1** is the join point (needs 1.2 + 2.2).
- **Phase 6 docs** (6.1 / 6.2) may be drafted by parallel doc subagents once 5.1 is green, then reconciled.

**Isolation:** subagents that mutate files run against the shared working tree in dependency order; concurrent implementers (e.g. 1.1 ∥ 2.1) touch disjoint paths (`convex/schema.ts` vs `app/ConvexClientProvider.tsx`) so they don't conflict. If two concurrent steps would ever touch the same file, serialize them instead.

**Boundaries:** the two USER-RUN steps (**0.2** `npx convex dev`, **5.2** Vercel/prod deploy) are interactive-auth and are NOT delegated to subagents — the orchestrator pauses and surfaces the exact command for the user to run, then resumes.

**Orchestrator ledger:** after each verifier passes, the orchestrator flips that step's `[ ]`→`[x]` in this file, so the doc stays the live source of build truth.

### Step 1.2 — `convex/subscribers.ts` (subscribe mutation)  [x]

**Prerequisites:** 1.1
**Inputs:** `convex-spec.md` §4, §7
**Outputs:** `showcase/convex/subscribers.ts`

**Implementation:**
- Export `subscribe = mutation({ args: { email: v.string(), source: v.optional(v.string()) }, handler })`.
- Handler:
  1. `const email = args.email.trim().toLowerCase();`
  2. `const source = args.source ?? "unknown";`
  3. Validate: if `!EMAIL_RE.test(email)` → `throw new Error("invalid email")` (generic; client maps to its own copy).
  4. Dedup: `const existing = await ctx.db.query("subscribers").withIndex("by_email", q => q.eq("email", email)).unique();` — if `existing`, `return { ok: true };` (silent idempotent success; no insert, no throw, no enumeration leak).
  5. Insert: `await ctx.db.insert("subscribers", { email, createdAt: Date.now(), source });`
     - Add the Resend-seam comment here: `// FUTURE (Resend phase): ctx.scheduler.runAfter(0, internal.emails.sendWelcome, { email })`
  6. `return { ok: true };`
- Define `EMAIL_RE` locally (mirror of the client regex per conventions).

**Acceptance criteria:**
- [x] `subscribe` validates server-side and throws on invalid email.
- [x] Duplicate email (case/space-insensitive) inserts nothing and returns `{ ok: true }` without throwing.
- [x] New email inserts exactly one row `{ email(lowercased), createdAt, source }`.
- [x] Resend-seam comment present; NO email/scheduler code added.
- [x] `convex dev` reports the function deployed; it appears in `_generated/api`.

## Phase 3 — Form integration

### Step 3.1 — Wire `NewsletterForm` to the mutation  [x]

**Prerequisites:** 1.2, 2.2
**Inputs:** `showcase/components/composites/NewsletterForm.tsx`, `convex-spec.md` §5
**Outputs:** `showcase/components/composites/NewsletterForm.tsx` (modify)

**Implementation:**
- Add `source?: string` to `NewsletterFormProps`; default `"unknown"` in the destructure. (Keeps `<NewsletterForm />` valid.)
- `import { useMutation } from "convex/react";` and `import { api } from "@/convex/_generated/api";`
- `const subscribe = useMutation(api.subscribers.subscribe);`
- Add a `pending` state (`useState(false)`).
- Make `onSubmit` async:
  1. `e.preventDefault()`.
  2. Keep the local `EMAIL_RE` guard → on fail set the existing "a valid email, please" error and return (no network).
  3. Clear error, set `pending = true`.
  4. `try { await subscribe({ email: email.trim(), source }); setSubmitted(true); }`
     `catch { setError("the ink did not take — try again"); }`
     `finally { setPending(false); }`
- Disable the input + button while `pending`; apply reduced opacity to the button (`opacity: pending ? 0.6 : 1`) and `cursor: pending ? "default" : "pointer"`. Do not change the button label (per spec default).
- Leave all other markup, styles, a11y wiring (`useId`, `aria-invalid`, `aria-describedby`, `role="alert"`, `visuallyHidden` label, `noValidate`) untouched. The error `<p>` already renders for `error` — reuse it for the failure copy.

**Acceptance criteria:**
- [x] Invalid email still shows "a valid email, please" and makes NO network call.
- [x] Valid submit calls `subscribe({ email: trimmed, source })`.
- [x] On resolve → existing "Inscribed…" confirmation renders.
- [x] On reject → "the ink did not take — try again" shows via `role="alert"`, confirmation does NOT render, entered email is preserved.
- [x] Input + button are disabled during the in-flight call.
- [x] `<NewsletterForm />` with no props still typechecks and renders.
